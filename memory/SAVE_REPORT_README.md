# Save Report Module Documentation

This module provides functionality for generating high-quality, well-structured markdown reports from research data.

## Overview

The `save_report` module enables you to:

- Generate richly formatted markdown reports with consistent structure
- Track evidence from multiple sources (documents and web results)
- Include verification status with confidence scores
- Automatically sanitize and validate inputs for security
- Manage report files with unique timestamp-based naming

## Core Components

### 1. Data Classes

#### `EvidenceItem`

Represents a single piece of evidence with source attribution.

```python
@dataclass
class EvidenceItem:
    source: str           # Source identifier (file path, URL, etc.)
    content: str          # The actual evidence content
    score: float          # Relevance/confidence score (0.0 to 1.0)
    source_type: str      # Type of source ('document' or 'web')
    snippet_length: int   # Maximum length of content to display
```

#### `ReportConfig`

Configuration for report generation with sensible defaults.

```python
@dataclass
class ReportConfig:
    max_content_length: int = 10000    # Maximum length for content fields
    max_snippet_length: int = 1000     # Maximum length for snippets
    max_gaps_display: int = 5          # Maximum number of gaps to display
    sanitize_control_chars: bool = True # Remove control characters
    preserve_whitespace: bool = False   # Preserve whitespace formatting
```

### 2. Type Aliases

- `JsonDict = Dict[str, Any]` - JSON-compatible dictionaries
- `EvidenceChunk = Dict[str, Any]` - Document evidence chunks
- `WebResult = Dict[str, Any]` - Web search results
- `VerificationStatus = Dict[str, Any]` - Verification status info
- `ReportMetadata = Dict[str, Any]` - Report metadata

## Main Functions

### `save_report()`

Saves a research report to a markdown file.

```python
def save_report(
    content: str,
    query: str = "",
    session_id: str = "default",
    state: Optional[Dict[str, Any]] = None,
    output_dir: Optional[Path] = None,
    config: Optional[ReportConfig] = None
) -> str:
    """Save a research report to a markdown file with comprehensive structure."""
```

**Parameters:**
- `content` (str): The report text to save
- `query` (str): Original user query for filename generation
- `session_id` (str): Session identifier for tracking
- `state` (Optional[Dict]): Evidence and metadata from orchestrator
- `output_dir` (Optional[Path]): Custom output directory
- `config` (Optional[ReportConfig]): Configuration for generation

**Returns:** Absolute file path where report was saved

**Raises:**
- `OSError`: If there's an error creating directories or writing
- `ValueError`: If content is None or empty

### `build_enriched_markdown()`

Builds a markdown report string without saving.


## Error Handling

The module includes comprehensive error handling:

- Invalid input types are logged and handled gracefully
- JSON parsing errors are caught and logged
- File I/O errors raise `OSError` with detailed messages
- Empty or whitespace content is logged as a warning

## Security Features

- Control character removal (null bytes, escape sequences)
- Text length truncation to prevent DoS
- Path validation for file operations
- Input type checking before processing

## Best Practices

1. **Always sanitize user input** before passing to `save_report()`
2. **Use state dictionaries** to include rich evidence data
3. **Set appropriate max lengths** based on your use case
4. **Log report paths** for tracking and debugging
5. **Use session IDs** to correlate related reports
6. **Check verification status** to assess report reliability

## Migration from Previous Versions

If you're upgrading from a previous version:

1. Update function signatures to use new type hints
2. Replace `state` dict structure with new format
3. Use `ReportConfig` for configuration
4. Update file path handling to use `Path` objects

## Performance Considerations

- Large evidence chunks are truncated automatically
- JSON parsing is wrapped in try-except blocks
- File I/O is synchronous (consider async for high-volume use)
- Statistics generation iterates through all files
